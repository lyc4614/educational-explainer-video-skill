# 素材与动效复用

`material-library/` 存放静态图像与检索元数据；按帧运动、图表和合成逻辑位于代码中。两者配合可以减少重复制图，但每次复用都要重新核对语义、时间和空间。总体结构见[工程思想与架构](工程思想与架构.md)，制作步骤见[从SRT到成片](从SRT到成片.md)。

## 素材库能提供什么

打开 `material-library/index.html` 可离线检索、筛选与查看图像；`catalog.json` 是机器可读目录，`assets/` 保存原始PNG。素材数量和类型以当前目录为准，不把历史压缩包的计数写死到检查逻辑中。

| 类型 | 能直接做的事 | 需要另行准备的事 |
| --- | --- | --- |
| 透明主体 | 作为独立整体平移、缩放、旋转、淡入淡出，叠加可编辑标注 | 关节动作、转身、道具拆分、另一视角 |
| 完整场景 | 整体展示、推近、裁切，叠加标题与字幕 | 把背景中的单个角色或物件独立运动 |
| 代码组件 | 按当前帧计算运动、卡片、曲线、柱形和环形 | 当前稿件的数据来源、合适的图表关系与具体布局 |

3D风格PNG是一张二维静态图。人物可以作为整体移动，不能据此宣称它会行走、抬手或操作器材；包含多人和桌子的图像也可能只是一个整体层。真正需要独立动作的对象，应另行拆层或生成，完成透明度和边缘检查后再使用。

## 按语义选图

先确定当前镜头的来源句和解释任务，再检查素材的 `uses`、`cautions`、标签、轮廓、朝向与分辨率。标题、文件名和原提示词有助于检索，但不证明当前段落中的事实。

复用时保留这些语义限制：

- 校园、宿舍、体育器材和学习场景是概念图，不代表某所真实学校的设施、课程或招生承诺。
- 学生和教师形象不代表真实个人，也不证明学习成绩或教育效果。
- 天平、显微镜、化学模型等适合作为概念载体，不能未经核实用作精密结构或实验步骤示意。
- 书本、分支、表针、路线和拼块的数量与形状不自动对应现实科目数、具体时刻、政策路径或结论。
- 文具包可以解释准备行为，不能当作某场考试的准带物品清单；手机收纳图不能自动推出注意力改善的因果结论。
- 原图里没有具体数据或公式时，使用可编辑图层补充已核实内容，不把装饰模型当成数值证据。

选择新的角色时也要通过“移除测试”：删掉它是否让解释变难？如果没有，它可能只是在占空间。素材库用于按需选择，不要求一条视频用齐所有图片。

## 入库保留原图和测量结果

每项采用稳定ID，保存文件、SHA-256、尺寸、素材类型、透明信息、可见边界和锚点，同时保留可获得的提示词、来源说明、适用语义及限制。提示词缺失就标记缺失，不补写一个看似原始的提示词。

从实际PNG重新测量，例如从仓库根目录运行：

```sh
node scripts/inspect-asset.mjs material-library/assets/report.png --id report --kind cutout --out qa/report-inspection.json
```

这里的 `report.png` 是待替换的项目文件示意，需指向实际存在的PNG。检查器需要可用的 `sharp` 依赖；按脚本支持方式安装或提供模块位置。检测结果只能证明脚本实际检查的字节、alpha与边界，不能证明图像没有视觉问题或有何版权保证。

透明素材还需在深、浅两种底色上检查：是否真的透明？是否有棋盘格、白边、裁切、残影、异常阴影或不需要的文字标记？只有元数据而没有读到实际图片时，检查状态应保持 `metadata-only`，不能写成像素验证通过。

原图不覆盖。标注、裁切、改色和合成另存为项目派生文件；按字节哈希去重，原图复制到视频项目时校验哈希一致。公开素材目录的文件与来源字段使用相对路径，避免带入私人机器目录、用户原稿或凭据。使用条件请阅读[根目录LICENSE](../LICENSE)；本文及提示词记录不授予额外权利。

## 按可见边界定位

假设图片可见边界为 `(bx, by, bw, bh)`，希望主体可见宽度为 `w`，中心放在 `(cx, cy)`：

```text
scale = w / bw
imageLeft = cx - (bx + bw / 2) * scale
imageTop  = cy - (by + bh / 2) * scale
```

图片元素的缩放后宽高仍由完整画布尺寸乘以 `scale` 得到。旋转轴使用同一个可见中心，避免一转就绕着透明空白区摆动。当前目录可能使用 `bbox.left/top`，通用组件使用 `bounds.x/y`；接入时做明确的字段适配，不把两个对象直接混用。边界阈值和测量方法以实际检查器结果为准。

仓库 `assets/layered-primitives/motion.mjs` 的 `placeImage` 与 `VisibleAsset.tsx` 提供这一思路。主体、阴影、标注、连接线应由同一份姿态计算；不能主体已经停靠，标签仍用旧坐标。检查碰撞时还要考虑旋转后外接范围和阴影，不能只检查未旋转的中心点。

## 复用运动机制

把 `assets/layered-primitives/` 中需要的组件复制到当前项目后再适配，PNG放进当前项目的 `public/` 并通过项目相对资源路径加载。不要依赖作者电脑上的绝对目录。

`travelPose` 计算由当前帧确定的弧线移动；`LayeredExample.tsx` 展示主体入场、停靠、数据出现的组合思路。调用者仍要提供素材、时间、布局和已核实数据。中间态模式用于保留数据空间、检查主体；最终合成应接入数据图层，避免把“只看素材运动”的状态当作完整解释交付。

长段落通过同一个主体ID承接多个规则，保持相邻阶段共享姿态，检查位置及速度连续；有意切镜则明确改变构图。需要变换焦点时，可从整体关系转到资料细节或选择视角，但裁切放大仍是同一张PNG，不是新的角色姿势。

## 复用图表机制

`assets/chart-primitives/geometry.mjs` 负责纯几何，`ChartLayer.tsx` 提供可适配的SVG覆盖层。当前项目负责数据、单位、时间窗、标题、来源说明和数据矩形。图表实验室中的完整演示场景展示运动思路，正式合成时只取需要的图表部分。

| 机制 | 使用约束 |
| --- | --- |
| 柱形 | 明确 `maximum` 和零基线；比较对象的单位、年份、批次和统计范围一致 |
| 折线 | 明确横轴含义和数值域；沿实际折线描绘，游标走同一路径；不等距观察另做横坐标映射 |
| 环形 | 明确整体；完整组成可用 `donutArcs`，单个占比用要求 `whole` 的 `shareArcs`；未报道余量保持中性 |
| 标签 | 保留源字符串的单位、近似词与精度；历史值不随入场进度计数 |

通用图形支持的非负数据不能直接用于负值、正负混合或不同基线；这些情况需要扩展坐标和几何实现再测试。演示中的固定项数与短标签也不保证任意数据自动排好，长标签或密集图例必须重排并检查手机观看效果。

环形先按完整整体计算最终扇区，再用扫描进度揭示这些固定扇区。不要只对已经出现的类别归一化；强调可以变色或小幅平移，不能改变面积。柱形和折线同样不应弹跳越过定量终点。`whole=100` 代表百分比尺度，不代表推断出100名样本。

数值几何与可见标签需要分别核对：几何可能使用数字字段，标签保留来源原文。更换数据时同时更新这两者及来源说明，不能只换大数字而留下旧形状。

## 新增或替换后的最小回归

素材替换先重测实际PNG并检查深浅底，确认可见边界和项目内复制字节；再检查入场、最大移动、停靠、数据展开、阅读停留和退出。旧卡片与替代图表需互斥，主体让出的数据区也要在下一镜干净归还。

行为测试覆盖共享边界、结果出现时机、精确标签、分母与图形比例；视觉复核覆盖边缘、标注和字幕安全区。最后一次源码修改后运行最终回归，再对新版导出文件做完整媒体校验和实际向前播放。保留原图、旧版成片和检查范围，具体交付步骤见[从SRT到成片](从SRT到成片.md#验收与版本回归)。
